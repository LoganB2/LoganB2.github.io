Multi-Sensor TV Attribution Fusion

A next-generation TV attribution system that fuses four independent measurement methods into one weekly estimate of incremental impact — with real uncertainty intervals instead of a single over-confident number.

Bayesian Statistics numpyro Python Causal Inference

01 Problem

Standard TV attribution relies on a single measurement method, which produces a single number with no signal for how much to trust it. Different methods have different blind spots — a model can look confident while being systematically wrong in a way its own methodology can't detect. Clients needed an estimate of TV's incremental impact on sessions, orders, and revenue that was honest about its own uncertainty.

02 Approach

  • Designed four independent "sensors," each deliberately built on a different methodology so they don't share the same failure mode: a minute-level web-traffic-spike method, a TV-panel exposed-vs-matched-control comparison, a household-level case-control method using viewing data, and a deterministic scan-based matching method.
  • Built a Bayesian fusion layer (using numpyro) that combines the four sensors' estimates into one weekly total with credible intervals, plus a diagnostic gauge that distinguishes "the sensors disagree with each other" from "every sensor is individually noisy."
  • Restricted outputs to raw incremental totals only — no cost-per-result metrics — so downstream dashboards compute derived metrics from a single consistent source rather than the model making assumptions about cost allocation.
  • Built allocation breakdowns (by creative, daypart, and geography) and a "false-attribution waterfall" that quantifies how much of the prior production model's claimed impact is statistical artifact rather than real lift.

03 Technical Highlights

  • Deliberately uncorrelated sensor design — each of the four measurement methods fails differently, so agreement between them is real evidence, not four ways of making the same mistake.
  • Bayesian fusion with honest intervals — rather than averaging point estimates, the fusion layer propagates each sensor's own uncertainty into the combined credible interval, and a companion gauge explains what's driving a wide interval when one occurs.
  • False-attribution waterfall — a specific analysis decomposing how much of the existing production model's claimed impact would still show up even with no real causal effect, making the case for change legible to non-technical stakeholders.
  • Modular pipeline architecture — each sensor lives in its own small, single-purpose module with one orchestrator notebook tying them together, so sensors can be validated, debugged, or swapped independently.

04 Outcome

All four sensors were built and validated end-to-end on the first client, with fusion producing a full set of weekly estimates and credible intervals across the validation window. Allocation tables and the false-attribution waterfall are complete. The system is now being extended from one validated client to the rest of the client roster.
