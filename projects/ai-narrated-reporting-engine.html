AI-Narrated, Fact-Audited Reporting Engine

One reporting engine replacing four scattered, manually-maintained report builders — every client report gets an AI-written narrative that's allowed to cite only facts that have already been verified against the source data.

LLM Integration Python Databricks Report Automation

01 Problem

Client reporting across TV and streaming campaigns — covering both media delivery and performance — was spread across several separate, one-off report builders, each with its own formatting and manually written narrative sections. That meant duplicated logic, inconsistent client experience, and narrative text that was slow to produce and easy to get subtly wrong.

02 Approach

  • Built one parameterized pipeline that generates all four report variants (linear/streaming crossed with delivery/performance) from a shared codebase instead of four separate ones.
  • Every report starts as a deterministic "fact packet" — computed directly from the data, with no AI involved — before any narrative is written.
  • An LLM then writes the narrative on top of that packet, constrained to cite only facts that are actually present in it; every generated claim is automatically re-audited against the packet afterward as a hallucination check.
  • Combines a client's full campaign portfolio into one interactive HTML report with tabs, charts, competitive context, milestones, and reach — plus editable per-campaign summary snapshots for account teams.
  • Wired report delivery to route to the right internal teams automatically, and archives every sent report so results feed a downstream viewer app.

03 Technical Highlights

  • Fact-packet / narrative separation as a guardrail — by computing every number deterministically before the LLM ever sees the data, and restricting it to only cite what's in that packet, the design turns hallucination from an open-ended risk into something that can be mechanically checked.
  • Automated claim auditing — every narrative is re-checked claim-by-claim against the source fact packet after generation, so drift or subtle misstatement gets caught before a report ships, not after a client notices.
  • One pipeline, four report shapes — parameterizing the linear/streaming × delivery/performance matrix into a single codebase eliminated the divergence that came from maintaining four independently evolving builders.
  • Production safety discipline — the live scheduled version of the pipeline syncs to a production job within seconds of any change, so changes to it are made deliberately and only when intended to go live immediately.

04 Outcome

Feature-complete: all four report types have been migrated from their legacy builders and validated against prior outputs, including combined multi-campaign reports. The system is in final validation on live data ahead of a full production swap, and a next-generation viewer app payload has already been packaged and handed off for deployment.
